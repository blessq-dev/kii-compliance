# Прототип: автоматизированная оценка соответствия значимых объектов КИИ

Прототип к магистерской ВКР (ИТМО, ФБИТ). Метод: формализованная база правил (YAML)
+ движок правил (Python), отделённый от интерфейса (Streamlit).

## Что делает

1. Пользователь вводит сферу деятельности и показатели значимости объекта.
2. Движок определяет категорию значимости по ПП РФ № 127.
3. По категории формируется базовый набор мер из приложения к приказу ФСТЭК № 239.
4. Пользователь отмечает реализованные меры → отчёт о несоответствиях со ссылками на источник.

## Установка и запуск (для пользователя, Windows)

1. **Установите Python 3.11 или новее** с https://www.python.org/downloads/.
   В первом окне установщика отметьте галочку **«Add python.exe to PATH»**.
2. **Скачайте программу:** на странице репозитория нажмите зелёную кнопку
   **Code → Download ZIP** и распакуйте архив в любую папку.
3. **Запустите `run.bat`** двойным щелчком.
   - Первый запуск ставит нужные библиотеки (нужен интернет, 1–3 минуты).
   - Затем в браузере откроется программа: http://localhost:8501.
   - Чтобы завершить работу, закройте чёрное окно консоли.

Если Windows покажет «Система Windows защитила ваш компьютер» — нажмите
«Подробнее» → «Выполнить в любом случае».

### Как пользоваться

1. Слева введите наименование объекта и выберите сферу деятельности.
2. **Шаг 1** — заполните показатели значимости, которые применимы к объекту
   (неприменимые оставьте пустыми). Подсказка «?» у поля — пункт ПП № 127.
3. **Шаг 2** — система сразу показывает категорию и объясняет, почему.
4. **Шаг 3** — отметьте меры защиты, реализованные на объекте.
5. **Шаг 4** — «Сформировать отчёт»: список несоответствий со ссылками
   на приказ ФСТЭК № 239; отчёт можно скачать.

Для знакомства: слева «Демонстрация» → выберите объект → «Загрузить пример».

## Запуск для разработчика

```
pip install -r requirements.txt
streamlit run app.py        # интерфейс
pytest                      # тесты
python experiment.py        # эксперимент: метрики на тестовом наборе
```

| Папка / файл | Назначение |

| `docs/` | Нормативные документы — единственный источник требований |
| `notes/` | Выжимки из документов с замечаниями при переносе |
| `rules/categorization.yaml` | 21 значение 14 показателей ПП № 127 + общие правила п. 6–7 |
| `rules/measures.yaml` | 152 меры в 17 группах с категориями (приказ № 239) |
| `rules/spheres.yaml` | Сферы деятельности субъектов КИИ (187-ФЗ, ст. 2, п. 8) |
| `engine/rules_loader.py` | Загрузка базы правил |
| `engine/categorization.py` | Категорирование (ПП № 127) |
| `engine/measures.py` | Базовый набор мер по категории (приказ № 239, п. 23) |
| `engine/assessment.py` | Оценка соответствия и текст отчёта |
| `engine/metrics.py` | Метрики: accuracy, recall, precision |
| `engine/dataset.py` | Чтение тестового набора |
| `app.py` | Интерфейс (только ввод/вывод, без логики) |
| `run.bat`, `.streamlit/config.toml` | Запуск двойным щелчком; настройки Streamlit (только localhost) |
| `experiment.py` | Прогон тестового набора, расчёт метрик, CSV с результатами |

## Метрики для ВКР

- **Время оценки.** Система: `experiment.py` (автоматический прогон) и `data/results/sessions.csv`
  (время от начала ввода до отчёта в интерфейсе). Вручную: поле `minutes`
  в `data/manual_results.yaml`.
- **Точность категорирования** — доля объектов с категорией, совпавшей с эталоном.
- **Полнота (recall)** — доля эталонных несоответствий, найденных системой.
- **Точность (precision)** и **доля ложных несоответствий** (1 − precision).

`experiment.py` считает метрики и для системы, и для ручной оценки (когда она заполнена).

## Принятые решения

- **Нормативка применяется буквально.** Места, где текст документов внутренне противоречив
  (ПП № 127: п. 5, 9а, 14; приказ № 239: мера ДНС.5), перенесены дословно, а движок выводит
  по ним замечания в отчёт. Подробно — раздел 3 в `notes/pp127_categorization.md`
  и `notes/fstek239_measures.md`.
- **Редакции:** ПП № 127 — исходная (2018); приказ № 239 — ред. от 09.08.2018 № 138.
  При замене документов в `docs/` обновляются только `notes/` и `rules/`, код не меняется.
- **Сфера вне 187-ФЗ** → объект не подлежит категорированию (187-ФЗ, ст. 2, п. 8; ПП № 127, Правила, п. 2).
- **Пустой показатель** = неприменим к объекту (ПП № 127, Правила, п. 6, абз. 3).
- **Только базовый набор мер.** Адаптация набора под угрозы, компенсирующие меры и дополнение
  мерами иных НПА (п. 23, 26 Требований) не автоматизируются — это ограничение прототипа.
